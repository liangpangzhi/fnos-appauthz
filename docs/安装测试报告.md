## 四、真机暴露并修复的问题（6 个）

| # | 问题 | 现象 | 修复 |
| --- | --- | --- | --- |
| 1 | `wizard/uninstall` 里 `"initValue": false` 用了布尔值 | 安装只报 `code 10111`（`APP_INSTALL_FAILED_PKG_EXCEPTION`），无任何细节；`install-local` 才能看到真实原因：`cannot unmarshal bool into Go struct field WizardConfig.items.initValue of type string` | 改为字符串 `"false"`，最终改为 `switch` 类型 + `"initValue": "false"`；并且 `wizard/uninstall` 不再放输入项（见 #5） |
| 2 | `trimacl` 不在 PATH（位于 `/usr/trim/bin`） | `shutil.which("trimacl")` 返回 None → 静默降级成 `setfacl`，而 fnOS 1.2 的 Trim-ACL 用 getfacl 读不出来 | 增加 `/usr/trim/bin` 等目录的兜底查找，所有 ACL 命令使用绝对路径 |
| 3 | 误以为要递归 `-R` | `trimacl -R` 直接报 `invalid option -- 'R'` | trimacl 的 ACE 带 `sfd` 继承标志，子文件/子目录自动继承（实测子文件可读），递归选项只在 setfacl 下使用 |
| 4 | 撤销方式错误 | 原实现 `trimacl -x a:u:<uid>` 不符合语法；真实用法是按 **ACE 序号** 删除 | 先 `trimacl <path>` 解析 ACE 列表拿到序号，再 `trimacl -x<序号> <path>` |
| 5 | CLI 卸载被卡住 | `wizard/uninstall` 含输入项时：`Failed to uninstall appauthz, please uninstall it from Web UI.`（`appcenter-cli uninstall` 没有任何参数可传） | `wizard/uninstall` 改为纯 `tips`，说明配置/日志位置 |
| 6 | 巡检与账户匹配的两个 bug | ① 巡检用 `app.name`（显示名“影视”）去比对 `/var/apps`，全部误报“应用已卸载”；② `Aellus` 这种大写应用名匹配不到系统账户 `aellus`（uid 986） | ① 改用 `app_name` 比较、显示名单独用于展示；② 账户候选名增加小写回退 |

另：数据库真实结构比文档多一列 `authorization_path.trimacl_perm`（bigint，系统自身写入的 rw 记录为 `0`），已按系统行为一并写入，避免列不一致。

## 五、fnOS 打包/安装的几条硬规则（实测）

1. **fpk 文件名必须是 `<appname>-<version>-<arch>.fpk`**，与 manifest 对应。
2. **`wizard` 里所有 `initValue` 必须是字符串**（`"false"` 而非 `false`），否则整个包装不上，且只报 10111。
3. 用 `appcenter-cli install-fpk` 安装时**同版本不能覆盖**，会直接提示 `Application [x] is installed.`。
4. **`appcenter-cli uninstall` 不接受任何参数**，若包内 `wizard/uninstall` 有输入项就无法卸载。
5. `appcenter-cli install-local -d <解包目录> -e <env> -v <卷号>` 会**先卸载再安装**，是覆盖升级测试的可用路径。
6. `install-local` 的错误信息比 `install-fpk` 详细得多 —— 排错优先用它。
7. 该机 SSH 关闭了端口转发（`direct-tcpip: Administratively prohibited`），无法做隧道；本文档的界面验证在本地同版本代码 + 真实数据快照下完成。

## 七、v1.0.1：桌面图标空白 / 点开提示“无法访问”的定位过程

用户反馈：「程序无法打开，拒绝访问，桌面图标为空」。拆成两个独立问题，都已定位到根因。

### 7.1 图标为空 —— 文件名用了连字符

对照系统自带应用即可看出规范：

```
$ ls /usr/local/apps/@appcenter/trim.media/ui/images/
icon_{0}.png   icon_16.png  icon_24.png  icon_48.png  icon_64.png
icon_72.png    icon_96.png  icon_128.png icon_256.png

$ cat /usr/local/apps/@appcenter/trim.media/ui/config
{".url": {"trim.media": {"icon": "images/icon_{0}.png", "type": "url", "url": "/v", ...}}}
```

`{0}` 会被替换成尺寸，所以文件必须叫 **`icon_64.png`（下划线）**。
1.0.0 的包生成的是 `icon-64.png` / `icon-256.png`（连字符），系统按 `icon_64.png` 找不到 → 桌面只画一个空底色块。

**修复**：`tools/make_icons.py` 改为输出 `icon_{16,24,32,48,64,72,96,128,256}.png`，外加一份字面量 `icon_{0}.png` 兜底（与系统应用一致），根目录 `ICON.PNG` / `ICON_256.PNG` 保持不变。真机安装后已确认落盘：

```
$ ls /var/apps/appauthz/target/ui/images/
icon_{0}.png icon_16.png icon_24.png icon_32.png icon_48.png icon_64.png
icon_72.png icon_96.png icon_128.png icon_256.png
```

### 7.2 打不开 / 拒绝访问 —— 端口没转发出来

第三方应用的界面是独立端口（`http://NAS:18080`），不走 5666。这台测试虚拟机用 QEMU user 网络，实际只映射了部分端口：

```
$ python scripts/open_port.py --list      # QMP info usernet
TCP[HOST_FORWARD] * 5666  → 10.0.2.15 5666
TCP[HOST_FORWARD] * 2222  → 10.0.2.15 22
```

本机上 `curl http://127.0.0.1:18080/` 直接连不上（`000`），所以桌面点图标必然是“无法访问 / 拒绝访问”。

**处理**：QEMU 支持运行时通过 QMP 热加端口转发，不需要重启虚拟机：

```
python scripts/open_port.py              # hostfwd_add net0 tcp::18080-:18080
→ 已添加转发：本机 *:18080 → 虚拟机 :18080

curl http://localhost:18080/  → 200
curl http://localhost:18080/api/ping → {"ok":true,"version":"1.0.1",...}
```

同时把 `18080` 写进了启动器配置 `fnnas-data/config.json` 的 `forward_ports`，重启虚拟机后仍然生效。

### 7.3 走过的弯路（结论已写进 README）

曾尝试让应用复用 5666：在 `/usr/trim/nginx/conf/conf.d/` 里加一个 `location /appauthz/` 反代。
文件写入成功，但**执行 `nginx -t` 的瞬间就被删除** —— fnOS 的 `trim_recover` 模块会恢复/清理该目录，属于反篡改保护。
结论：不要往系统 nginx 配置里加东西，第三方应用老实走独立端口。这条已回退，包内不再触碰任何系统配置。

### 7.4 顺带修掉的小问题

- 界面版本号一直显示 `v1.0.0`：原来读的是初始化时写进 `settings.json` 的旧值，改为启动时从 `/var/apps/<name>/manifest` 读取，现在显示 `v1.0.1`。
- 前端接口路径从 `/api/xxx` 改为按当前路径相对解析（`API_BASE`），以后若要挂到子路径下也不会 404。

### 7.5 回归结果

- `scripts/live_test.py` 只读 / 读写两套用例：**各 24/24 通过**。
- 真机浏览器打开 `http://localhost:18080/` 正常渲染（见 `docs/screenshot-live-login.png`、`docs/screenshot-live-grant.png`）。
- 「失效清理」在真机上报出 **2 条真实失效记录**（`/vol2/1000-1-214faa07`、`/vol02/1000-1-00fd125e`，卷已不存在），非误报，未擅自删除，留给用户在界面里自行清理。

## 八、v1.0.4：取消登录密码（免密码登录）

需求：不想每次打开都输管理密码。

做法：新增设置项 `no_login`（默认关闭），而不是删掉密码校验——密码保留，随时能关回去。

| 入口 | 用法 |
| --- | --- |
| 界面 | 诊断与设置 → 参数设置 → **免密码登录** 开关，保存即生效 |
| 命令行 | `manage.py auth --mode off|on|show`（写入 settings.json，运行中的进程下次请求即读到） |

实现要点：

- `Handler.logged_in()` 增加 `settings.get("no_login")` 判断，为真则直接放行；
- `/api/ping`、`/api/state`、`/api/diagnose` 三处都带上 `no_login` / `has_password`，供界面判断（诊断页原来只读自己的 settings，漏了这两项，已补）；
- 免登录状态下「管理密码」卡片只显示“设置新密码”，不需要原密码（此时本来就不校验原密码）；
- 顶栏挂红色「免登录」标签做安全提醒，鼠标悬停有说明；
- `Settings.get()` 增加了 mtime 比对，命令行改完立刻生效，不用重启应用——万一密码忘了也能自救。

真机验证（v1.0.4）：

```
$ curl -s http://localhost:18080/api/ping          # 不带任何 Cookie
{"ok":true,"version":"1.0.4","no_login":true,"has_password":true,"logged_in":true}

$ manage.py auth --mode on                          # 关闭免登录，不重启
$ curl -s -o /dev/null -w '%{http_code}' http://localhost:18080/api/state
401

$ manage.py auth --mode off                         # 再打开
{"ok":true,"no_login":true,"logged_in":true}
```

顺手修掉：部分应用显示名是数据库里的 i18n 占位符（`"${common.display_name}"`），
现在优先取 `manifest.display_name`，其次 `app.i18n_matadata` 里的 `zh-CN.DisplayName`，再退回 `app_name`；
真机上 9 个应用全部显示正常（影视 / 115网盘 / Node.js v22 / 夸克下载器 …）。

安全提醒已写进 README：应用以 root 运行，免登录等于“能访问该端口即可改授权”，
只在可信内网或本机端口时使用。

## 九、v1.0.6：多文件夹批量授权 + 选择器修复

### 9.1 需求

一次给多个应用授权多个文件夹（原来只能一次一个目录）。

后端其实早就是 `apps × paths` 的双层循环，`_paths_from_body` 也接受 `paths`
数组并做了去重与根目录校验 —— **缺的只是界面**：输入框只有一个，提交时只发 `path`。

### 9.2 改动

| 位置 | 内容 |
| --- | --- |
| 前端 | 路径区变成「多行列表」：`＋ 添加路径` 增行、每行 `✕` 删除、「浏览…」把选中的目录填进空行或追加一行；提交时发 `paths` 数组 |
| 确认框 | 显示 `N 个应用 × M 个目录 = N×M 条授权`，并列出全部目录 |
| 去重 | 同一路径重复添加会提示"该路径已在列表中"，不重复写入 |
| 后端 | 无需改动（已支持），仅把 `APP_VERSION` 更到 1.0.6 |

### 9.4 顺带修掉的两个真 bug

1. **弹窗点不动**：`.modal` 上写了 `onclick="event.stopPropagation()"`，而所有点击都委托在
   `document` 上 —— 冒泡被掐断，弹窗里每一行、每个按钮都收不到事件（表现就是"鼠标点文件夹没反应"）。
   去掉内联调用即可；关闭遮罩原本就靠 `e.target === el` 判断，不需要拦截冒泡。

2. **`/vol` 不等于所有卷**：根目录校验把 root 当"目录前缀"比较，`/vol1` 不以 `/vol/` 开头，
   于是所有卷都被判成"不在允许范围内"，点了目录只会弹错误提示。现在 `/vol` 按卷通配处理
   （正则 `^/vol\d+(/|$)`，`/vol1abc`、`/volumes` 仍会被拒），并补了单元测试：

```
OK  /vol1/1000/电影 -> True     OK  /vol1abc  -> False
OK  /vol00          -> True     OK  /etc/passwd -> False
OK  /volume1/x      -> True     OK  /volumes/x  -> False
```
